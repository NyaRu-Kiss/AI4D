# 第 5 章：治理与评测

治理把前面各章的控制点收成可以检查的制度：哪些风险要管、用什么证据证明管住了、出事时先关什么。

## 5.1 公开框架怎么用

NIST AI RMF 1.0 于 2023-01-26 发布，定位是自愿采用的框架，用来在设计、开发、使用和评价中纳入可信考虑。配套有 Playbook、路线图和交叉对照。2024-07-26 发布的 NIST AI 600-1 是生成式 AI 轮廓。2026-04-07 的页面还提到关键基础设施可信 AI 轮廓的概念说明，并写明 AI RMF 1.0 正在按白宫 AI 行动计划修订。使用时以 NIST 当前文本为准，不把某一份培训幻灯片里的摘要当成控制项清单。来源：<https://www.nist.gov/itl/ai-risk-management-framework>（2026-10-30）。

对本白皮书，框架的用法是：每个场景有所有者（治理），有数据、动作和错误成本的地图（映射），有评测和线上指标（度量），有降级、回滚和人工接管（处置）。具体职能名称以 1.0 正文和后续修订为准。

OWASP Top 10 for LLM Applications 2025 的条目名称，在项目页上可以核对：

| ID | 名称 | 在 AI4D 里的主要控制点 |
| --- | --- | --- |
| LLM01 | Prompt Injection | 资料与指令分离；工具网关 |
| LLM02 | Sensitive Information Disclosure | 数据分类、过滤、日志脱敏 |
| LLM03 | Supply Chain | 依赖、模型和权重来源 |
| LLM04 | Data and Model Poisoning | 知识审核、微调数据来源 |
| LLM05 | Improper Output Handling | 输出当数据，不当命令或 HTML |
| LLM06 | Excessive Agency | 自主性等级和工具白名单 |
| LLM07 | System Prompt Leakage | Prompt 里不放秘密；泄漏不是唯一防线 |
| LLM08 | Vector and Embedding Weaknesses | 索引权限、重建、隔离 |
| LLM09 | Misinformation | 引用、拒答、人工抽检 |
| LLM10 | Unbounded Consumption | 步数、Token 和费用预算 |

来源：<https://genai.owasp.org/llm-top-10/>（2026-10-30）。

## 5.2 评测

评测集从需求的正例和反例生长，不从模型的自我演示生长。每条样本包含：输入、允许的资料、身份、期望行为、禁止的行为。

| 检查 | 问题 |
| --- | --- |
| 任务 | 该完成的事是否完成 |
| 证据 | 事实句是否有对应引用 |
| 拒答 | 无依据时是否停止 |
| 权限 | 越权样本是否在检索前被挡住 |
| 工具 | 参数是否符合 Schema，写操作是否发生了不该发生的次数 |
| 成本 | Token、检索和时延是否在预算内 |

离线评测进 CI。线上按场景抽样，人工看自动评分判为通过但用户修改了的例子。自动评分规则本身也要版本化。评分模型和被测模型是同一个时，记录这个事实，避免把自评分当成独立证据。

DORA 2025 报告的公开摘要说，AI 放大的是组织已有的交付能力。评测门禁弱的团队，加上 Coding Agent 之后，进入主干的缺陷也会变多。来源：<https://dora.dev/research/2025/dora-report/>。2026-10-30 的 <https://dora.dev/ai/> 另把《ROI of AI-assisted Software Development》标成最新报告。该报告正文未打开，不把它的框架写进门禁。

## 5.3 观测最少字段

请求标识、租户、场景、模型版本、Prompt 版本、知识版本、切片标识、工具名、策略决定、人工是否改过、用量和延迟。生成式 AI 的遥测字段名跟随 OpenTelemetry GenAI 语义约定的当前仓库。2026-10-30 的旧文档页声明该约定已经迁出、旧页不再维护：<https://opentelemetry.io/docs/specs/semconv/gen-ai/>。

日志默认不保存完整客户正文。排障需要正文时，使用有期限的、访问被审计的附件，而不是永久索引。

## 5.4 应急

按这个顺序收口，避免先重写 Prompt：

1. 关掉写工具或把场景降到只读。
2. 停止扩大灰度。
3. 按兼容矩阵回滚代码、Prompt、知识或索引中真正改变的那几项。
4. 保留 Trace 和相关知识版本。
5. 把失败样本写入评测集，再修。

模型不可用时，标准请求仍可由人按 Runbook 处理。检索不可用时，不改成“让模型凭参数知识回答制度问题”。

## 5.5 工具如何接入

| 类别 | 接在哪 | 要求 |
| --- | --- | --- |
| 离线评测 | CI | 失败不能由被测变更自己改阈值 |
| 在线 Trace | 模型客户端和工具网关 | 能串起版本和工具 |
| 实验记录 | 模型、Prompt、索引的比较 | 记录数据集版本 |
| 防护栏 | 输出之后、工具之前 | 规则可单测；不替代授权 |

产品对照见工具附录。

## 5.6 退出条件

- 场景所有者、评测门槛和降级开关都有名字。
- OWASP 表里和本场景相关的行有对应控制，或写明为何不适用。
- 应急顺序写在值班手册里，并演练过关写工具。
