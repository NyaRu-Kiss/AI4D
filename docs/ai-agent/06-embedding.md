# 4.6 Embedding

Embedding 把文本或其它对象映射到向量，使“语义上相近”的对象在选定的距离下更接近。距离近只说明模型空间里的邻近，不说明内容为真，也不说明用户有权阅读。

## 4.6.1 方法论

一个索引绑定一种 Embedding 模型、一种预处理和一种距离。这三项写进索引版本。更换模型、更换是否归一化、或更换维度，都要重建索引，并用同一组查询比较新旧召回。两个模型的向量不能写进同一个索引再一起搜索。

至少区分三类向量，不要混用同一套预处理却假装它们相同：

| 向量 | 输入 | 用途 |
| --- | --- | --- |
| 文档向量 | 切片 | 入库 |
| 查询向量 | 用户问题或改写后的查询 | 检索；有的模型要求查询和文档使用不同的提示或前缀 |
| 实体向量 | 术语或实体名 | 链接到图节点，不代替文档切片 |

距离和归一化按模型说明使用。说明要求归一化后再用点积时，索引和查询都要归一化。不要在没有模型说明的情况下同时尝试三种距离并挑选好看的演示。

领域差：通用模型对条款号、内部产品名和代码标识符往往不如关键词。所以 Embedding 和关键词并列，而不是取代第 4.4 节的混合召回。多语言场景用同一多语言模型编文档和查询，并准备每种语言的查询样本。

公共榜单（例如 MTEB 一类的嵌入评测）用来了解模型在公开任务上的相对情况。生产选择以场景查询集为准：召回率、越权是否被过滤挡住、延迟和费用。榜单名次不写入本文，除非检索笔记引用了页面上的原句。

有的系统用晚交互：查询和文档各保留一组向量，在查询时再计算细粒度匹配。它通常比单向量更重。只在双编码器加关键词的评测仍然漏掉表格、版面或精确措辞时，才作为候选，并单独评估索引体积和延迟。

维度缩减或可变维度只有在模型文档说明支持时才使用，并且缩减后的索引是另一个版本。

## 4.6.2 AI Coding 技巧和注意点

技巧：

- 在管道里记录模型名、版本、维度和预处理哈希。查询服务启动时检查这些字段和索引元数据一致，不一致就拒绝启动。
- 用一组固定短文做冒烟：同一句话的两种说法应比无关句子更近。这个测试只检查接线，不证明业务召回。
- 批量嵌入失败要可重跑，以原文哈希为幂等键，避免半截索引被当成完整版本。

注意点：

- 把整个文件嵌成一个向量，长制度的局部条款会消失。切片策略见知识库一章。
- 查询日志里的原文可能含个人数据。向量有时可以被反推或被用作成员推断的材料，日志和索引按数据分类保护。OWASP 2025 将向量和嵌入弱点列为 LLM08。
- 为了省钱用更小的模型时，用同一评测集比较，不只用演示问题。

## 4.6.3 工具如何接入

嵌入调用放在知识管道和查询服务两处，共用一个客户端。客户端只返回向量和模型标识。调用方负责批大小、重试和超时。托管 API 和本地模型走同一个接口。

对照表收录本次打开过文档的模型家族和评测方法，见工具附录。没有打开模型卡的，不写优点。

## 4.6.4 退出条件

- 索引元数据含模型、维度、距离和知识版本。
- 换模型的操作手册包含重建和评测，禁止在线混写。
- 冒烟测试和一组真实查询的召回记录随索引版本保存。
