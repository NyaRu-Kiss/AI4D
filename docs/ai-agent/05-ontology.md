# 4.5 Ontology

标号 ③。本节以知识库 `KnoledgeVault/technical/ontology` 已写的定义、边界、L0–L5、四种姿态和工程生命周期为底稿，收成白皮书的一章。已经打开过 LICENSE 或 README 的工具写在 [tools.md](../reference/tools.md) 第 17 节。

## 4.5.1 本体负责什么

Ontology（本体）是对某个领域概念化结果的显式、形式化、可共享的规范说明。知识库笔记把它拆成四层：

1. 概念化：领域里有哪些对象和关系。
2. 显式：概念、定义和关系写出来。
3. 形式化：机器能解析、查询和推理。
4. 可共享：多个系统和团队复用同一套语义。

它解决的是“大家说的是不是同一个概念，以及从这个概念能推出什么”。它不负责把订单存进哪张表，也不负责一句自然语言和哪一段文档更相似。

## 4.5.2 和相邻技术的分工

| 技术 | 它回答的问题 | 典型产物 |
| --- | --- | --- |
| 数据库 Schema | 数据怎样存放 | 表、列、索引 |
| JSON Schema | 一次输入输出长什么样 | 字段和类型 |
| Taxonomy | 概念怎样分层 | 父类、子类 |
| SKOS | 术语怎样称呼和管理 | 首选词、别名、映射 |
| Ontology | 概念和关系的正式含义 | 类、属性、公理 |
| Knowledge Graph | 具体事实如何连接 | 实体和关系；通常是 T-Box 加 A-Box |

数据库可以把国际订单和普通订单放在一张表或两张表里。本体仍然可以表达“国际订单是订单”。因此本体适合做多个存储之间的共同语义层。

SKOS 管理“这个概念叫什么、有哪些别名”。OWL 管理“这个概念在逻辑上有什么关系和限制”。SKOS 的 Concept 不会自动变成 OWL 的 Class。术语冲突先做 SKOS 或术语表，确认需要推理之后再引入类公理。

知识图谱如果只有事实、没有稳定的语义模型，仍然可以查关系，但跨团队会重新争论边的含义。

T-Box 描述概念、关系和公理。A-Box 描述具体实例和事实。两者分开之后，规则演进、业务事实更新、推理重算和数据迁移可以独立进行。知识库中的例子：

```text
T-Box：国际订单是订单；订单可以发往城市
A-Box：订单#20240927 是国际订单，发往上海
推理：订单#20240927 也是订单
```

表达力从 RDFS 到 OWL 2 的各个轮廓逐步增强，建模、推理和治理成本一起增加。从业务问题选择轮廓，而不是从表达力最强的语言开始。

## 4.5.3 能力问题

建模从能力问题开始：模型必须能回答的问题。知识库笔记的例子包括“哪些订单发往上海”“哪些订单缺订单号”“某个术语有哪些别名”。每个问题映射到所需的类或属性和一种验证方式：

| 能力问题 | 需要的模型 | 验证 |
| --- | --- | --- |
| 查询发往某城市的订单 | 订单、城市、发往 | SPARQL 或等价图查询 |
| 判断订单是否缺号 | 订单号 | SHACL 或应用校验 |
| 国际订单也是订单 | 子类公理 | 推理测试 |

回答不了能力问题的本体文件，只是一份还没进入工程的草稿。

## 4.5.4 L0–L5

这是介入深度，不是必须一次建完的平台。知识库中的升级路线：

| 层级 | 本体承担的职责 | 进入信号 |
| --- | --- | --- |
| L0 | 不参与，依赖 Prompt 和朴素 RAG | 概念简单、关系少、错误成本低 |
| L1 | 术语、同义词、字段映射 | 同义词导致召回或接口不稳定 |
| L2 | JSON Schema、Pydantic 或 MCP 契约 | 工具参数和输出格式经常错 |
| L3 | 图关系、SPARQL 或 GraphRAG，与关键词、向量一起召回 | 问题需要多跳关系 |
| L4 | OWL 推理、SHACL、业务规则 | 需要隐含结论或高风险拦截 |
| L5 | 候选知识、审核、版本、发布 | 知识持续变化且必须审计 |

L1 解决“叫什么”，L2 解决“长什么样”。两者通常先于 L3。L4 里三件事不要并成一个引擎：

- OWL 推理负责语义上的隐含事实。
- SHACL 检查数据或输出的形状是否合格。
- 应用规则处理流程判断，例如金额阈值和审批级别。

违规结果按风险阻断、告警或转人工。推理结果要和原始事实分开存储或分开标记，回答时能说明结论来自公理还是来自文档。

L5 的前提：有本体所有者、候选区、人工审核、版本和回滚、查询/推理/校验回归、证据和来源。Agent 发现的新实体和新关系先进入候选区。

知识库对三条路线的比较：

| 方案 | 优点 | 主要风险 |
| --- | --- | --- |
| 一开始建设完整 OWL | 表达力强 | 建模和治理成本过高 |
| 只用向量 RAG | 上线快 | 术语、关系和输出约束不足 |
| 按 L0–L5 分阶段 | 成本和问题匹配 | 需要持续判断该不该升级 |

当前推荐分阶段。每一级都要能回退到上一级的行为。

## 4.5.5 四种接入姿态

姿态描述职责，可以同时使用，不是 L0–L5 的别名。

| 姿态 | 管什么 | 常见落地 |
| --- | --- | --- |
| Contract | 工具边界、字段和结构 | MCP Schema、JSON Schema |
| Index | 实体、关系和召回路径 | 图检索、BM25、向量的组合 |
| Guardrail | 输出是否合法 | SHACL、规则校验 |
| Memory | 新知识如何进入正式本体 | 候选区、审核、版本发布 |

一个订单 Agent 可以同时：工具字段用 Contract，沿订单—客户—区域用 Index，输出金额和订单号用 Guardrail，新别名用 Memory 进入候选术语。处于 L3 的系统可以只有 Contract 和 Index。启用 Memory 的条件是已经有 L5 的治理，而不是模型声称它记住了。

## 4.5.6 工程生命周期

知识库把本体当成软件资产：

```text
业务问题 → 能力问题 → 术语和概念 → 类与属性 → 公理和约束
→ 示例数据 → 查询、推理、校验测试 → 版本发布 → 监控和变更
```

模块按领域拆开，例如订单、客户、地理、术语、校验形状。复用外部本体时记录版本、许可证、来源和映射，不把一个会变化的外部地址当成编译期依赖。

版本至少包含 ontology IRI、version IRI、变更日志、兼容性、弃用策略、推理器与 SHACL 引擎版本。新增类通常较容易兼容。删除类、重命名属性、修改定义域或值域、增加互斥或基数限制，会改变查询和推理结果，要有迁移和回归。

| 测试 | 目的 |
| --- | --- |
| 语法 | 文件能被解析 |
| 结构 | 必要的类和属性还在 |
| SHACL | 正例通过，反例失败 |
| 查询 | 能力问题仍能回答 |
| 推理 | 隐含事实保持稳定 |
| 一致性 | 公理和事实不冲突 |
| 性能 | 数据增长后仍在目标时间内 |

发布顺序：提交、自动解析和校验、回归、人工评审、发布版本、迁移 A-Box、监控查询和校验结果。

## 4.5.7 AI Coding 技巧和注意点

技巧：

- 让模型根据访谈草稿列出候选类、关系和还没回答的能力问题。人决定哪些关系进入 T-Box。
- 让模型把一条能力问题写成 SPARQL 或 SHACL 草稿，用正反例运行，不接受没跑过的形状文件。
- 用模型检查新公理和旧测试的差异说明。说明不能代替测试。

注意点：

- 模型会把每张表都生成一个 OWL 类，并把所有约束写成公理。能用 JSON Schema 或 SHACL 表达的形状，不要先写成开放世界下很难检验的逻辑约束。
- 开放世界里，“没有说”不等于“没有”。缺订单号这类约束用 SHACL 或应用校验，不依赖推理器替你封闭世界。
- 生成的本体 IRI 和示例网址不能直接当生产标识。标识由所有者分配。
- 不要把 A-Box 里的一条客户事实自动提升为 T-Box 公理。

## 4.5.8 工具如何接入

知识库技术栈笔记把链路分成：建模、RDF/OWL/SKOS 文件、图存储、SPARQL、推理器、SHACL、业务 API、Agent。文件是源，数据库里的图可以由文件装载。Agent 通过业务 API 或 MCP 工具查询和校验，不直接获得推理器的管理接口。

笔记里的四种落法：

| 落法 | 组合 | 适合 |
| --- | --- | --- |
| 学习 | RDFLib、Protégé、pySHACL | 验证三元组、建模和校验 |
| 轻量生产 | RDF 存储、SPARQL、SHACL、业务 API | 共享语义和数据质量 |
| 推理 | 选定的 OWL 轮廓、存储、推理器、SHACL | 隐含关系和一致性 |
| Agent | 术语、Schema、图检索、向量检索、校验器、证据存储 | 工具契约和带证据的回答 |

RDF 存储以三元组和 SPARQL 为中心，语义和推理有公开标准。属性图以节点、边和属性为中心，路径和事务更直接，推理通常要自己做。需要跨系统交换语义和标准推理时用 RDF。需要工程图和现有 Cypher 技能时用属性图，并单独写明哪些约束由应用保证。

Jena、RDFLib、pySHACL、Oxigraph、RDF4J 的本次检索结果在工具附录第 17 节。Protégé、GraphDB、HermiT、ELK、RDFox、Neo4j 的许可证页还没有打开。

## 4.5.9 退出条件

- 已选择停留的层级，并写明升级信号。
- 能力问题有对应测试。
- OWL、SHACL 和应用规则的分工写在 ADR 里。
- 若启用 Memory，候选区和所有者已经存在。
