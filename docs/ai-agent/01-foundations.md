# 4.1 Agent 基础

Agent 是 AI System 的运行时形态。它在 Scene 允许的状态里观察输入、决定下一步、调用工具，并根据结果继续或停止。

## 4.1.1 三种系统不要混名

| 类型 | 下一步由谁决定 | 有没有外部副作用 | 失败时 |
| --- | --- | --- | --- |
| 聊天机器人 | 模型生成下一段文本 | 没有，或只有人复制出去 | 再问一次 |
| 工作流 | 流程定义 | 有，但是预先声明的活动 | 按活动策略重试、补偿或转人 |
| Agent | 模型在允许的动作里选择 | 可有，必须经工具网关 | 要有步数上限、检查点和人工接管 |

一个产品可以同时包含三者：工作流保存订单状态，其中一个活动调用检索式问答，另一个活动只在人确认后写入备注。把整条订单流程叫做“一个 Agent”会让权限和恢复无法设计。

## 4.1.2 方法论

一次 Agent 任务拆成五个可观察的部分：

1. 感知：当前用户输入、允许的检索结果、工作流状态。
2. 计划：模型给出的下一步。计划可以只存在于图的一条边上，不必先写成长篇计划再执行。
3. 执行：一次工具调用或一次对用户的回复。
4. 反馈：工具结果、校验结果、人的确认。
5. 停止：达成验收、步数用尽、校验失败、人拒绝，或预算用尽。

自主性等级沿用第 1 章：只读、建议、受控写入、高影响动作。等级写在工具上，不写在模型的自我描述里。

状态要能在进程重启后恢复。恢复的是已完成的工具调用和它们的幂等键，不是把模型上次的内心独白重放一遍。

## 4.1.3 AI Coding 技巧和注意点

技巧：

- 先用固定工作流和假工具把状态跑通，再把其中一个不确定步骤换成模型。
- 工具描述写成契约：作用、参数、副作用、错误。用三个例子测试模型是否选对工具。
- 为循环设置最大步数和最大工具失败次数。到达上限时把已收集的证据交给人。

注意点：

- 多 Agent 会增加通信和调试成本。一个场景里如果下一步其实是固定的，不要拆成多个互相对话的角色。
- 模型报告“已完成”不等于外部系统已改变。完成以工具的成功回执和业务验证为准。
- 把上一轮的工具结果原样累积进上下文，会挤掉任务本身。只保留后续步骤需要的字段。

## 4.1.4 退出条件

- 已经声明这个场景是聊天、工作流活动，还是带工具选择的 Agent。
- 停止条件和步数上限已写进设计。
- 每个工具的副作用等级已登记。
