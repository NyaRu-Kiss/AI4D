# 4.7 Agent Architect

标号 ①。本节把第 1 章的参考架构落到 Agent 运行时：状态、工具、策略、知识、模型和业务系统如何组合。Architect 在这里是结构，不是一个新的岗位。

## 4.7.1 控制面和执行面

| 面 | 包含 | 不包含 |
| --- | --- | --- |
| 执行面 | 模型路由、检索、重排、草稿生成、在白名单内的工具调用 | 授予自己新权限 |
| 控制面 | 身份、策略、确认、评测门槛、预算、审计、降级开关 | 生成业务答案 |

模型客户端不持有生产库凭证。凭证在工具网关，按调用身份和策略版本发放。网关记录工具名、参数摘要、决定和回执。

来自用户、文档和工具结果的文本都视为数据。系统指令只来自已发布的 Prompt 版本。这是为了降低提示注入把“资料”变成“命令”的机会。注入仍然要靠权限和输出校验收口，OWASP LLM01 和 LLM06 是运营和设计的检查项。

## 4.7.2 组合模式

| 模式 | 模型决定什么 | 适合 | 代价 |
| --- | --- | --- | --- |
| 路由器 | 在少数已知处理器里选一个 | 问题类型清楚 | 类型增多后路由本身会错 |
| 计划—执行 | 先列步骤再执行 | 步骤不太长、且每步可检查 | 计划过时后仍照做会放大错误 |
| 图状态机 | 在设计好的节点上选择或填写 | 需要耐久执行和人工插入 | 要维护图和状态 |
| 多 Agent | 多个角色通过明确接口协作 | 技能边界稳定、需要隔离权限 | 通信、重复上下文和排障成本 |
| 仓库 Coding Agent | 在工作区里改代码并跑检查 | 有规格、有测试的开发任务 | 会扩大差异和读取秘密，必须限制权限 |

LangGraph 的公开文档把它定义为底层编排运行时，用来在同一张图里混合确定性步骤和模型步骤，并提供持久执行、流式输出和人工介入。它不是唯一的图运行时。是否采用，取决于团队是否需要这种控制，以及是否接受该生态的升级成本。文档：<https://docs.langchain.com/oss/python/langgraph/overview>（2026-10-30）。

Agent 之间的协作如果要跨进程、跨团队且不暴露内部工具，使用显式协议，而不是共享 Prompt。Agent2Agent（A2A）是 Linux Foundation 下的开放协议，仓库说明它用 JSON-RPC 2.0 over HTTP(S)，通过 Agent Card 发现能力，并声明与 MCP 互补：MCP 面向工具，A2A 面向 Agent 之间的协作。许可证页面为 Apache-2.0。来源：<https://github.com/a2aproject/A2A>（2026-10-30）。内部模块调用不必上 A2A。

## 4.7.3 和 Scene、本体姿态的对应

| 架构决定 | 落点 |
| --- | --- |
| 哪一步可以调用模型 | Scene 的状态 |
| 工具字段和错误形状 | Contract（L2） |
| 检索用文档、图或两者 | Index（需要多跳时才是 L3） |
| 输出能否进入下游 | Guardrail |
| 新术语进不进正式知识 | Memory，且只有 L5 的审核存在时 |
| 写操作是否发生 | 工作流里的人工任务或策略网关 |

幂等键由业务动作产生，例如“工单编号 + 动作 + 目标版本”。网关用它拒绝重复提交。人拒绝之后，状态回到工作流的上一步，而不是让模型换一种说法再提交。

## 4.7.4 AI Coding 技巧和注意点

技巧：

- 先画状态和工具白名单，再让模型生成编排代码。生成物必须把每条边的失败写出来。
- 用假工具做可重复测试：成功、超时、冲突、空检索。
- 策略用表或代码表达，能在不调用模型的情况下单测。

注意点：

- 隐性重试会把一次扣款或一次通知变成多次。重试策略在网关，不在 Prompt。
- 多 Agent 互相把输出当指令，会形成注入链。下游 Agent 的系统指令不接受上游的自由文本覆盖。
- 循环没有步数和预算上限时，一次故障会变成 LLM10 所说的无界消耗。
- 上下文里堆积完整工具 JSON，会把任务挤出窗口。持久化状态，只把摘要放进下一次调用。

## 4.7.5 退出条件

- 控制面和执行面的边界写进 ADR。
- 选定的模式能说明为什么不是更简单的那一档。
- 工具白名单、幂等、步数和预算有测试。
- 跨 Agent 的协议只在需要互操作时引入。
