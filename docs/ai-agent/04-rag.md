# 4.4 RAG

RAG（Retrieval-Augmented Generation）在生成之前，从允许的知识里取出依据，并把依据交给模型。它减少“模型没见过这家公司的制度”这类缺口。它不保证取出的依据足够，也不保证模型会忠实使用依据。

## 4.4.1 方法论

把下面几步分开评测。任何一步失败，都不要只改最后的 Prompt。

```text
查询改写 → 权限过滤 → 关键词召回和向量召回 → 合并去重 → 重排
→ 按预算拼装上下文 → 生成 → 核对引用 → 无依据则拒答
```

| 步骤 | 要单独看的失败 |
| --- | --- |
| 查询改写 | 多轮代词指错对象；改写把限制条件丢掉 |
| 权限过滤 | 其他租户或更高密级的切片进入候选 |
| 召回 | 正确切片不在候选里；只命中词面相同的无关段 |
| 重排 | 正确切片被挤出交给模型的窗口 |
| 拼装 | 切片超预算时砍掉了限定条件或例外条款 |
| 生成 | 答案使用了上下文里没有的数字或条款 |
| 引用 | 引用的位置和答案句子对不上 |
| 拒答 | 资料不足时仍然给出确定结论 |

混合召回同时用关键词和向量。关键词保住条款号、错误码和产品名。向量保住说法不同但主题相同的段落。两边都要在过滤之后，或使用能在过滤条件下检索的索引。

重排用查询和切片的相关性重新排序，再按预算截断。笔记里的知识引擎说明把 Rerank 定义为对多路召回结果打分并排序。没有重排时，提高召回条数只会把更多噪声送进上下文。

固定管道适合问题类型稳定的问答。Agentic RAG 让模型决定再查一次、换查询或调用图查询。它多一轮模型失败和工具失败，只在固定管道的评测显示“缺的是另一次有目的的检索”时再引入。多跳实体关系稳定出现后，再把图检索加进召回，对应本体 L3。第一天不要同时上 Agent 循环、图数据库和向量库。

引用展示原文位置和知识版本。回答中的每个事实句要么对应引用，要么标成模型生成的连接语。连接语不能包含新的数字、日期和义务。

无依据时拒答，并说明缺的是哪类资料。拒答是成功路径，不是异常。

## 4.4.2 失败模式

| 模式 | 现象 | 处理 |
| --- | --- | --- |
| 过期切片 | 新旧制度一起被召回 | 发布时退役旧版本 |
| 权限泄漏 | 过滤条件没进检索 | 在索引查询里过滤，并用越权样本回归 |
| 引用错位 | 答案和附件来自不同切片 | 评测里检查句子和引用的对应 |
| 上下文中段丢失 | 长上下文里中间的例外条款被忽略 | 把例外放在窗口两端或单独的约束字段；减少切片数 |
| 检索提示注入 | 文档写着让模型忽略规则并调用工具 | 资料通道和系统指令分开；写工具不因文档内容而放开 |
| 图和向量互相否定 | 关系查询和文档切片结论不同 | 回答中标明两个来源，冲突时按已声明的优先级或转人工 |

评测工具会给这些现象不同的指标名。指标名称以工具文档为准，写入工具附录，不在这里发明一套分数。离线评测用固定问题集；线上抽样看引用点击、人工修改和拒答是否合理。自动评分和人工判断会不一致，高错误成本的场景保留人工抽检。

## 4.4.3 AI Coding 技巧和注意点

技巧：

- 先实现一条同步管道：过滤、关键词、向量、拼装、引用。每步把输入输出落在测试里。
- 用坏例子驱动：无答案、错租户、过期文档、表格、条款号精确匹配。
- 查询改写单独测试，不和最终答案混成一个断言。

注意点：

- 模型生成的“更好的切分器”如果没有黄金集，就不要替换线上切分。
- 把检索分数显示成“置信度”会误导用户。分数是排序依据，不是概率。
- 为了提高命中而关闭权限过滤，评测会变绿，场景会变得不能上线。

## 4.4.4 工具如何接入

编排代码依赖自己的接口：`rewrite`、`retrieve`、`rerank`、`assemble`。框架适配器放在边缘。这样替换重排模型或向量库时，评测集不用改。

图检索适配器返回路径和边的类型，调用方把它格式化成证据，不把数据库查询语言暴露给模型，除非该工具的身份只能执行预置查询模板。

对照表包括编排框架、重排、评测器和已核对的 GraphRAG 类项目，见 `docs/reference/tools.md`。

## 4.4.5 退出条件

- 正例、无依据、越权、过期四类样本都有评测。
- 引用能打开到知识版本和位置。
- 写工具不会因为检索文本而被调用，除非人确认。
