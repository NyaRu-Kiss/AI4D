# AI4D White Paper 提纲

> 检索日期：2026-10-30。本提纲只定结构，并点明每一节必须写到的内容。正文按章节展开方法论、AI Coding 技巧、工具接入和同类对照。
>
> 知识库对照：Obsidian `KnoledgeVault` 中已有本体 L0–L5、四种接入姿态、本体工程、腾讯 ADP/知识引擎 RAG 链路、上下文记忆分层、AIOps 闭环。这些内容并入对应章节，不另起一套术语。

## 怎么读每一节

每一节正文都按同一顺序写，提纲里不重复展开：

1. 这一层要解决的问题，以及它和上下层的边界。
2. 方法论：先判断什么、再产出什么、用什么标准验收。
3. AI Coding 技巧和注意点：人仍对合并、发布和副作用负责。
4. 工具如何接入：放在哪一层、用什么接口、哪些资产要版本化。
5. 同类工具对照表：角色、接入方式、优点、局限。不写未核对的跑分和价格。

## 1. AI4D

对应总览 `docs/ai4d-overview.md`。标号 ① 同时指向这里的总体架构，以及第 4.7 节 Agent Architect：Architect 是 AI4D 的落地形态，不是另一套体系。

必须写到：

- AI4D 的定义：交付的是可评测、可审计、可回滚的业务系统，不是单独的模型。
- 两条线：AI4 SDLC（过程）和 AI System（模型、知识、检索、工具、策略）。Scene 把二者接上。
- 与传统软件开发、数据工程、ML 工程的分工：谁拥有需求、数据、评测和线上动作。
- 角色只说明责任，不代替阶段方法：Product Owner、Solution Architect、前端、后端、AI / Agent 工程师、OPS。
- 核心产物：场景边界、资产清单、评测集、ADR、工具契约、发布与回滚说明。
- 参考架构：业务工作流、数据与知识、Agent 运行时、控制面（权限、评测、观测、发布）。
- 自主性分级：只读问答、建议、受控写入、高影响动作。风险决定确认和审计，而不是 Prompt。
- 选型方法：先约束（数据驻留、许可证、语言、CI、规模），再功能；用真实链路做最小验证。

## 2. AI4 SDLC

阶段负责人只是责任锚点。每一阶段的正文写该阶段里 AI Coding 的做法和失败方式。

### 2.1 Requirement（Product Owner）

`docs/ai-sdlc/01-requirement.md`

- 方法论：目标用户、触发、现状、期望结果、错误成本、数据来源、允许动作、验收方式。非目标和约束与目标同级。
- AI Coding 技巧：用模型起草用户故事、验收标准和竞品摘要；人确认事实、优先级和范围。禁止把模型补全的需求当成已确认需求。
- 注意点：虚构用户、漏掉合规和失败成本、把方案写成需求、验收标准无法测试。
- 产物：问题陈述、范围、成功指标、初版评测问题。
- 工具类别要对照：Issue/需求系统、规格驱动工具、文档协作。接入方式是需求文本进版本库，并链到后续评测用例。

### 2.2 Clarity

`docs/ai-sdlc/02-clarity.md`

- 方法论：把模糊请求拆成可验证问题。区分事实、推理、生成和执行。区分回答、辅助决策、自动执行和人工决策。
- AI Coding 技巧：示例映射、Given-When-Then、反例、术语表、澄清问答清单。用模型提出待确认问题，不替人做范围决定。
- 注意点：一个 Prompt 同时承担多种任务；没写拒答和越权条件；没形成 Scene。
- 产物：Scene 草稿、术语表、输入输出和异常、人机边界。

### 2.3 Design（Solution Architect）

`docs/ai-sdlc/03-design.md`

- 方法论：业务架构、应用架构、AI 架构分开画。数据流、知识流、模型调用、工具调用、失败和人工接管放在同一张决策里。
- AI Coding 技巧：用模型起草 ADR、时序和威胁清单；架构决定仍由 Architect 签署。先写上下文边界和工具权限，再选框架。
- 注意点：图代替架构；把框架对象泄漏进业务；没设计幂等、回滚和审计；Prompt 被当成授权。
- 产物：ADR、上下文边界、工具清单、评测与观测方案。
- 工具类别：ADR、C4/图表、威胁建模。图表进仓库，CI 只检查图能渲染，不证明架构正确。

### 2.4 Development（前端与后端）

`docs/ai-sdlc/04-development.md`

- 方法论：小任务、短反馈、可运行的检查。前端、后端、Agent 编排、知识管道分开评审。
- AI Coding 技巧：规则文件限定仓库惯例；任务说明带接口契约和验收命令；测试先行或至少同步补测试；一次变更一个问题；生成代码过格式、静态分析、测试、依赖和人工审查。
- 前端注意点：只生成看得见的界面却漏状态、权限、空态和错误态；把设计稿当数据契约。
- 后端注意点：幻觉 API、过期依赖、吞掉错误、在工具里直接做高风险写操作、密钥进上下文。
- Agent 开发注意点：工具 Schema、超时、幂等键、错误类型；结构化输出；模型路由；评测进 CI。
- 工具类别要对照：IDE/CLI Coding Agent、规则与仓库上下文、前端生成、API 契约与测试、SAST/密钥扫描。

### 2.5 Deploy

`docs/ai-sdlc/05-deploy.md`

- 方法论：代码、模型、Prompt、知识、索引、策略一起版本化，一起门禁，一起回滚。
- AI Coding 技巧：发布说明由模型起草，人确认兼容矩阵；评测失败不能被“只改文案”绕过；灰度看的是任务成功率和越权，不只是错误率。
- 注意点：只回滚应用镜像；索引和 Embedding 模型版本不一致；配置里的线上密钥被 Agent 读走。
- 工具类别：CI、GitOps、制品与模型注册、特性开关。接入点是合并门禁和发布流水线，不是开发者本机。

### 2.6 Operation（OPS）

`docs/ai-sdlc/06-operation.md`

- 方法论：请求、模型、Prompt 版本、检索证据、工具调用和动作串成一条 Trace。事故结论回写评测集、知识和 Runbook。
- AI Coding 技巧：用模型做告警摘要、相似案例和升级包；执行仍走授权、审批、验证和回滚。模型输出不是权限。
- 注意点：把聊天机器人接到生产 shell；观测日志留敏感正文；只监控延迟不监控质量和成本；幻觉和工具误用没有单独的事件类型。
- 与知识库中的 AIOps 对齐：Event、Alert、Incident、Request、Ticket 分开；L1/L2/L3 是处理深度，不是三个产品。
- 工具类别：Trace/评测、指标与告警、Runbook 与工单。

## 3. Scene

Scene 不是第三套流程。它是 SDLC 里 Clarity 和 Design 的稳定输出，并在运行时约束 Agent。

### 3.1 Business Workflow

`docs/scene/01-business-workflow.md`

- 方法论：角色、事件、状态、Agent 介入点、审批点、副作用、补偿。
- 判断：固定步骤用工作流引擎；开放式判断才放进 Agent。Agent 不替代状态机。
- AI Coding 技巧：从真实工单和操作录屏提取步骤时，必须人工删掉一次性例外；为每个写动作写成功条件和补偿。
- 工具类别：持久化工作流引擎、人工任务、审批。对照“引擎编排”和“Agent 循环”。

### 3.2 Data Center

`docs/scene/02-data-center.md`

- 方法论：数据所有者、分类、权限、脱敏、租户、保留和删除先于模型选型。
- 分层：业务库、文档与对象存储、分析平台、模型服务、知识服务、向量库、图存储、日志与审计。每层写它不负责什么。
- AI Coding 技巧：生成的数据管道要带样本校验和血缘；禁止用生产全量数据给 Coding Agent 当上下文。
- 工具类别：OLTP、对象存储、表格式/分析引擎、密钥与策略。点到为止，不把数据平台写成第二本白皮书。

## 4. AI Agent

### 4.1 Agent 基础

`docs/ai-agent/01-foundations.md`

- 聊天机器人、固定工作流、Agent 的区别：谁决定下一步，失败是否可恢复，有没有副作用。
- 感知、计划、执行、反馈。自主性等级和人工接管。
- 技巧：先用固定流程跑通，再把不确定步骤交给模型。工具描述写成契约，不写散文。

### 4.2 Model

`docs/ai-agent/02-model.md`

- 方法论：按任务选模型，而不是按参数规模。路由维度是质量、延迟、成本、数据驻留和工具调用稳定性。
- 基础模型、推理模型、小模型/专用模型各自适合的步骤。
- Prompt、检索、微调的选择顺序：先检索和评测，再考虑微调。
- 结构化输出、上下文预算、模型版本锁定。
- 工具对照：模型 API、路由网关、本地推理服务、结构化输出库。

### 4.3 Knowledge Base ②

`docs/ai-agent/03-knowledge-base.md`

标号 ② 表示这一节吸收知识库里已经写过的知识生命周期和腾讯知识引擎/ADP 链路，并补上通用做法。

- 方法论：来源、所有者、解析、切分、元数据、权限、有效期、审核、失效。
- 知识不是记忆：组织文档、会话历史、用户偏好、任务状态分开存。
- AI Coding 技巧：规范、ADR 和接口说明进知识库之前要有版本；Coding Agent 只检索与任务相关的片段。
- 工具对照：解析器、切分与入库框架、托管知识库。接入写清增量、删除、引用字段和训练使用边界。

### 4.4 RAG

`docs/ai-agent/04-rag.md`

- 方法论：改写、混合召回、过滤、重排、拼装、引用、拒答分开评测。
- 固定 RAG 与 Agentic RAG 的选择：后者多一次模型和工具失败面。
- 图检索何时加入：多跳关系稳定出现之后，而不是第一天。对应本体 L3。
- 失败模式：无关片段、过期片段、权限泄漏、引用和答案不一致、上下文中段丢失。
- 工具对照：编排框架、重排、评测器。评测指标只写工具文档里真实存在的名称。

### 4.5 Ontology ③

`docs/ai-agent/05-ontology.md`

标号 ③ 表示以知识库中的本体笔记为底稿，补标准来源和工具对照。

必须保留知识库中的框架，不改名：

- 定义：概念化、显式、形式化、可共享。本体、Schema、分类法、SKOS、知识图谱分工。
- T-Box / A-Box，能力问题（Competency Questions）。
- L0 无本体，L1 术语，L2 结构约束，L3 关系检索，L4 推理与校验，L5 治理演化。
- 四种姿态：Contract、Index、Guardrail、Memory。姿态不是等级，可组合。
- OWL 推理、SHACL 校验、应用规则三者分工。
- 工程：版本 IRI、回归测试、候选区、人工审核、回滚。
- 工具对照：建模器、RDF 存储、SPARQL、推理器、SHACL、属性图。RDF Store 与 Property Graph 的选择写进表。

### 4.6 Embedding

`docs/ai-agent/06-embedding.md`

- 方法论：向量表示相似度，不表示事实为真。文档向量、查询向量、实体向量分开。
- 版本锁：一个索引一种 Embedding 模型；换模型就要重建，并保留模型名和维度。
- 距离、归一化、多语言、领域差、Matryoshka 只在文档证实后写成可用手段。
- 评测：用真实查询集看召回，不只用公共榜单选生产模型。
- 晚交互（如 ColBERT 一类）作为可选路线，和双编码器对照。
- 工具对照：托管 Embedding API、开源模型、评测方法。不编造榜单名次。

### 4.7 Agent Architect ①

`docs/ai-agent/07-architect.md`

这一节把第 1 章的参考架构落到 Agent：状态、工具、策略、知识、模型和业务系统如何组合。

- 控制面与执行面分离。模型不持有执行权限。
- 模式：路由器、计划-执行、图状态机、多 Agent、面向仓库的 Coding Agent。每种写适合的不确定性和代价。
- 契约：MCP 或等价的工具协议；工具最小权限；写操作有确认、幂等和审计。
- 失败：提示注入、过度授权、隐性重试、循环不收敛、上下文污染。
- 和 Scene、本体四种姿态的对应关系。

### 4.8 Vector Database

`docs/ai-agent/08-vector-db.md`

- 职责：相似度召回和元数据过滤。不负责事实约束，不负责业务事务。
- 和方法：先过滤权限和租户，再做向量召回；或使用文档证实的过滤能力。混合检索要有关键词索引，而不是只存向量。
- 运维：分片、备份、扩容、重建索引、模型升级。
- 与文档库、关系数据库、图数据库的分工表。
- 工具对照：库内扩展、独立向量库、搜索引擎向量、托管服务。列部署形态、过滤、混合检索、多租户和许可证（只写核对到的）。

## 5. 治理与评测

`docs/governance/01-governance-eval.md`

- 数据安全、隐私、保留和删除。
- 幻觉、越权和工具误用。风险框架只采用核对过的公开条目（如 NIST AI RMF 的职能划分）。
- 评测集：任务成功、证据、权限、工具参数、成本和延迟。离线回归加线上抽样。
- 观测字段最少集：请求、模型版本、Prompt 版本、知识版本、检索片段、工具、动作、人工修改。
- 应急：停工具、降级到只读、回滚知识或模型、人工接管。
- 工具对照：实验跟踪、在线 Trace、离线评测、防护栏。
