# 2.6 Operation

负责人是 OPS。运营阶段保持系统在约定的质量、成本和权限内运行，并把确认过的失败送回需求和知识。

本节吸收知识库中的 AIOps 笔记（`01-ai-ops-overview`、`06-solution-comparison`）：AI 运维是可观测数据、资产关系、变更、知识和执行工具组成的可审计闭环。模型负责归纳和提出假设，策略和审批决定动作能不能发生。

## 2.6.1 先分开五类对象

| 对象 | 含义 | 例子 |
| --- | --- | --- |
| Event | 已经发生的事实 | 一次工具超时、一次索引构建完成 |
| Alert | 规则认为需要看的信号 | 拒答率或单次成本超过阈值 |
| Incident | 正在处理的服务异常 | 问答引用大量指向过期制度 |
| Request | 有明确目标的标准请求 | 重建某一租户的索引 |
| Ticket | 协作记录 | 事故单、服务请求单 |

一张工单不是运营系统的全部入口。监控事件也可以直接进入处理，不必先变成客服工单。

## 2.6.2 方法论

运行时每次请求尽量留下同一条 Trace 上的这些字段：请求标识、租户、场景、模型 ID、Prompt 版本、知识版本、检索到的片段标识、工具名和参数摘要、策略决定、人工是否修改过结果、Token 和延迟。字段的具体属性名对齐团队选用的遥测约定。OpenTelemetry 文档站点在 2026-10-30 说明，生成式 AI 语义约定已经迁到独立的 GenAI 语义约定仓库，旧页面不再维护：<https://opentelemetry.io/docs/specs/semconv/gen-ai/>。接入时以该仓库的当前约定为准，不把过期页面上的字段抄进代码。

四类闭环：

1. 信号到事件：先用规则检测，再去重和关联，然后才让模型做摘要。
2. 标准请求到 L1：只跑已经验证的 Runbook，核对身份和资源范围，验证结果。匹配不上就升级。
3. 事件到 L2/L3：L2 在责任域内用时间线和证据排查。跨系统、反复发生或无法复现的问题，升级包里要有排除项和风险，而不是一句现象。
4. 事故到治理：结论写成监控规则、Runbook、知识修订或架构改动，并用后续事件检查是否生效。

知识库笔记里的评审原则同样适用于工具选型：先定内部接口（事件、证据、知识、模型、策略、执行），外部产品经适配器进入。更换工单系统或模型供应商时，不重写处理等级和审计模型。

真实任务评审至少包括知识库笔记中的六类：身份相关的标准请求、带字段白名单的更新、可回滚的容量类故障、需要关联变更的错误率上升、模型和观测系统不可用时的人工降级、重复回调和丢失回执时的对账。

## 2.6.3 AI Coding 在运营中的技巧和注意点

适合模型做的事：

- 把多条告警收成一份带时间线的摘要，每条判断附上它使用的证据链接。
- 检索相似的已关闭事故和 Runbook，并显示版本。
- 起草升级包：已排除的原因、还没查的系统、建议的下一步。
- 根据复盘草稿列出应加入评测集的失败例子。

不能交给模型的事：

- 认定根因。模型可以提出假设，L3 的人确认后才回写规则。
- 在生产环境执行未登记的命令。执行网关是唯一写入口，带幂等、超时、Dry-run 和审计。
- 因为摘要“听起来像上次的故障”就自动回滚。回滚仍走 2.5 节的兼容矩阵。

OWASP《Top 10 for LLM Applications 2025》里和运营直接相关的条目，在 2026-10-30 的项目页上能核对到名称：

| 条目 | 运营上要看的现象 |
| --- | --- |
| LLM01 Prompt Injection | 用户或文档把工具调用带离原任务 |
| LLM02 Sensitive Information Disclosure | 回答或日志里出现不该出域的数据 |
| LLM05 Improper Output Handling | 模型文本被下游当成命令或 HTML 执行 |
| LLM06 Excessive Agency | 工具权限大于场景需要，模型自行做了高影响动作 |
| LLM08 Vector and Embedding Weaknesses | 检索被污染、权限过滤缺失或向量被滥用 |
| LLM10 Unbounded Consumption | Token、检索或循环工具调用没有预算 |

其余条目（供应链、数据投毒、系统提示泄漏、错误信息）放在第 5 章和开发门禁里处理。来源：<https://genai.owasp.org/llm-top-10/>。

其他注意点：

- 观测系统会复制敏感正文。保留期限、脱敏和访问范围按数据分类设置，不因为排障方便而永久保存完整 Prompt。
- 只监控延迟和可用性，会漏掉“又快又错”的发布。质量和成本是一等告警。
- 幻觉和工具误用使用单独的事件类型，避免混进通用的 5xx。

## 2.6.4 工具如何接入

| 类别 | 接在哪 | 要求 |
| --- | --- | --- |
| 指标、日志、Trace | 应用和工具网关 | 能用请求标识把模型、检索和工具串起来 |
| 告警 | 规则引擎 | 阈值有所有者和静默策略；模型摘要挂在告警上，不替代阈值 |
| 知识与 Runbook | 版本库或受控知识库 | 带来源、适用条件、风险和验证步骤 |
| 执行网关 | 所有写操作 | 策略版本、确认、幂等和回滚 |

产品对照见工具附录。知识库笔记强调：有聊天界面不等于具备事件关联、权限和回滚。

## 2.6.5 退出条件（进入稳定运营）

- 仪表板能回答：今天的任务成功率、拒答率、越权拦截、工具失败、单次成本。
- 值班表知道如何关写工具、如何回滚知识和模型、如何转人工。
- 复盘模板要求把确认的失败写回评测集或知识修订。
- 至少演练过一次“模型不可用”和一次“检索返回越权文档”。
