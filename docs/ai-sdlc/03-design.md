# 2.3 Design

负责人是 Solution Architect。设计阶段把 Scene 草稿收成可以开发的结构：数据怎么流、模型在哪一步被调用、工具有什么权限、失败时系统处于哪个状态。

## 2.3.1 三种架构不要画成一张宣传图

| 视图 | 回答的问题 | 必须标出的内容 |
| --- | --- | --- |
| 业务架构 | 谁在流程的哪一步负责 | 人工审批点、Agent 介入点、补偿责任人 |
| 应用架构 | 运行时有哪些服务 | 同步调用、队列、超时、谁保存任务状态 |
| AI 架构 | 一次回答用到哪些能力 | 模型路由、检索、重排、工具、校验、日志 |

三张图描述同一条请求的不同切面。只画到“用户 → Agent → 大模型”的图不能作为设计评审的材料。

## 2.3.2 方法论

1. 用 ADR 记录决定。每条 ADR 包含背景、决定、后果、被放弃的方案。被放弃的方案要写原因，避免下个季度用同一个框架重新争论。
2. 先定上下文边界，再选框架。写清一次调用允许模型看见的仓库目录、文档库、租户和工具名单。边界外的系统通过工具读，不把库表塞进 Prompt。
3. 数据流和知识流分开。业务事务走数据库和工作流。知识切片走解析、索引和引用。两条流用同一个用户身份做权限过滤，但存储和发布周期不同。
4. 工具按副作用分级，和需求里的自主性等级对齐。只读工具可以自动调用。写工具要有幂等键、超时、错误码和审计字段。高影响工具默认不暴露给模型，由人在界面上触发。
5. 失败路径和成功路径一起设计。模型超时、检索为空、校验失败、工具冲突、人拒绝，各自进入哪个状态，状态要能在工作流里看到。
6. 可靠性和成本是设计项。写目标延迟、单次 Token 上限、检索条数上限、降级后的行为（例如只返回检索片段，不再生成）。

威胁建模至少覆盖这些入口：

- 用户输入里的指令，试图让模型忽略系统约束。
- 文档和网页里的指令，在检索后进入上下文。
- 工具返回里的指令，试图让模型调用另一个工具。
- 过度授权的工具，使一次提示注入就能改数据。
- 日志和评测集把敏感正文扩散到更多系统。

设计的控制点放在工具网关、检索过滤和输出校验，不放在“系统 Prompt 里的禁止句”。

## 2.3.3 AI Coding 技巧和注意点

适合交给模型的草稿：

- 根据 Scene 列出候选组件和一张序列草图。
- 把一次设计讨论整理成 ADR 草稿，并单独列出讨论里没有结论的句子。
- 根据工具名单生成威胁清单的初稿。
- 检查序列图和 ADR 是否提到回滚。

Architect 仍要亲自定的内容：

- 状态存在哪里，进程重启后任务如何恢复。
- 哪个服务是写操作的唯一入口。
- 模型供应商不可用时的降级，是否允许换模型。换模型会改变工具调用格式和答案分布，要有评测，不能只改配置。
- 框架选择。编排框架表达状态和失败，不承载业务规则。业务规则留在本体、策略或普通代码里，避免锁死在某一个 Agent 框架的对象模型上。

常见失败：

| 失败 | 为什么危险 | 设计上怎么写 |
| --- | --- | --- |
| 图代替架构 | 没有权限和失败 | ADR 强制包含失败和回滚两节，没有这两节不能接受 |
| 框架对象泄漏 | 业务代码无法替换供应商 | 端口：Retriever、ToolGateway、ModelClient，适配器放在边缘 |
| Prompt 被当成授权 | 攻击者用文本绕过 | 网关按身份和策略过滤工具，Prompt 只描述任务 |
| 一次设计全部自动执行 | 错误成本被忘掉 | 每个写工具在图上标自主性等级 |
| 上下文无边界 | 秘密和过期代码进入模型 | 写允许的路径和文档集，默认拒绝其余 |

用 Coding Agent 生成图表时，图的源文件入库。CI 可以检查图能否被渲染。渲染成功不代表架构通过评审。

## 2.3.4 工具如何接入

| 类别 | 接入位置 | 要求 |
| --- | --- | --- |
| ADR | 仓库 `docs/adr/` | 编号、状态、日期；被接受的 ADR 变更走评审 |
| 结构图 | 仓库内的文本图源 | 能由人阅读差异；不把唯一副本放在白板工具里 |
| 威胁记录 | 跟对应 ADR 或 Scene 链接 | 每条威胁有控制点和验证方法 |
| 接口契约 | OpenAPI、JSON Schema 或 MCP 工具描述 | 和实现一起评审；Agent 生成代码时以契约为准 |

架构图和 ADR 产品这一轮没有单独打开产品页，所以上面的接入表就是设计阶段的工具做法。和设计产物一起用的规格工具、Coding Agent、MCP 见 [tools.md](../reference/tools.md)。

## 2.3.5 退出条件

- 至少一条被接受的 ADR，写明放弃方案。
- 工具名单带有副作用等级和确认方式。
- 失败和降级进入状态说明。
- 评测集的正例和反例已经挂到这条设计上。
- 观测字段清单已经列出，供 OPS 在第 2.6 节实现。
